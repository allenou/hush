# SearchKit 发布闭环与域名白名单设计

## 目标

将 SearchKit 1.0 的运行边界收紧到四个明确支持的搜索引擎域名，并修复发布审查中发现的功能、数据、隐私与商店描述不闭环问题，使首发版本具备可验证、可解释、可恢复的行为。

首发支持的搜索引擎为：

- Google：`google.com`、`www.google.com`
- 百度：`baidu.com`、`www.baidu.com`
- Bing：`bing.com`、`www.bing.com`
- 360 搜索：`so.com`、`www.so.com`

`www` 与根域名在产品语义和运行时匹配中视为同一域名，但 Manifest 中显式声明两个 hostname。首发不覆盖移动端、地区域名或任意子域名，例如 `m.baidu.com`、`cn.bing.com`、`google.com.hk`。

## 非目标

- 不开放用户添加、编辑或删除搜索引擎。
- 不申请运行时可选站点权限。
- 不重新设计 Popup 或 Options 的整体视觉。
- 不增加远程服务、同步、遥测或云端备份。
- 不删除旧版本存储中的 `customEngines` 字段，以保持备份和升级兼容。

## 运行范围与权限

### Manifest 白名单

Content Script 的 `matches` 和 `host_permissions` 使用相同的八个精确域名模式，只允许 `http`/`https` 下的根域名与 `www` 域名。移除 `<all_urls>`。

保留 `storage` 权限并移除 `activeTab`。Popup 查询当前标签页不需要 `tabs` 权限；受支持页面的 URL 由精确 host permission 提供，其他页面无法读取 URL 时显示中性不可用状态。

### 运行时二次保护

搜索引擎模块提供统一的 hostname 规范化与白名单判断。Content Script 启动时再次验证当前 hostname；非白名单页面不注入样式、浮动按钮、观察器，不扫描 DOM，也不记录搜索历史。

自动 DOM 检测继续用于四个内置引擎，以适应搜索结果 DOM 变化，但不再在任意网站运行，也不再自动持久化自定义引擎。

`ExtensionStorage.customEngines`、备份字段和现有存储规范化逻辑暂时保留，但首发运行时不读取或写入自定义引擎。

## 启用与禁用生命周期

`enabled` 表示搜索结果标记功能是否工作，不是整个扩展的总开关。搜索历史继续由独立的 `recordSearchHistory` 设置控制。

启用时：

- 初始化语言和注入样式。
- 注入浮动操作按钮。
- 检测搜索结果、广告和选择器规则。
- 创建受控的 MutationObserver。
- 在用户允许搜索历史时记录搜索。
- 向后台报告当前页面标记数量。

禁用时：

- 断开观察器并取消待执行的扫描定时器。
- 退出选择器 Picker。
- 移除结果按钮、弹出菜单、遮罩、徽标和折叠提示条。
- 清除当前标签页工具栏 Badge。
- 不读取结果 DOM、不扫描广告、不新增屏蔽统计。
- 保留浮动按钮；菜单替换为“启用标记”入口，点击后恢复标记功能。
- 保留 Storage 订阅和 SPA 导航监听。
- 搜索历史在 `recordSearchHistory` 开启时继续记录。

从禁用切换到启用时重新执行一次完整扫描初始化；从启用切换到禁用时清理标记层和扫描资源。初始存储即为禁用时，只创建用于重新启用的浮动按钮以及历史和存储监听，不创建扫描观察器。

## 搜索结果扫描

四个内置引擎仍通过自动检测确定结果容器和结果项。扫描仅在白名单 hostname 下进行。

广告扫描不得在未知页面运行。关闭“广告标记”时移除已有广告遮罩和广告徽标，并允许重新开启后重新识别；清理过程同时移除用于扫描去重的 `data-srb-*` 属性，避免关闭再开启后无法恢复标记。

SPA 地址变化时重置当前引擎、扫描状态和计数，再根据新 URL 重新检测；离开搜索结果路径后不得保留旧页面的折叠条或结果标记。

## 规则管理

### 规则搜索

规则搜索输入由父组件持有状态。`RulesTab` 通过回调上报输入变化，父组件据此重新计算 `filteredItems`。搜索同时匹配规则值和本地化后的类型名称。

### 输入规范化

添加规则前通过共享工具解析并规范化：

- 域名转小写并移除单个 `www.` 前缀。
- 拒绝包含路径的无协议域名输入，例如 `example.com/path`。
- 任何带协议且包含查询、hash、非根路径或显式端口的输入均作为 URL 规则。
- URL 由 `URL` API 规范化，保留查询和 hash，统一 hostname 大小写和默认端口行为。
- 根 URL（无查询、hash、非默认端口）作为域名规则。
- 重复判断基于规范化后的值。

### 选择器规则

Options 规则列表显示选择器规则所属 hostname，避免不同站点相同选择器无法区分。页面上的选择器徽标提供撤销入口，调用现有规则删除能力并立即恢复页面元素。

旧格式 `host||selector` 继续作为兼容表示，不改变备份版本。

## 搜索历史

搜索历史只记录四个内置引擎，并只受 `recordSearchHistory` 设置控制。关闭搜索结果标记不会停止历史记录。

导航检测覆盖：

- 首次完整页面加载。
- `popstate`。
- `history.pushState`。
- `history.replaceState`。

连续的相同“关键词 + 引擎”记录去重：若最新一条记录与当前搜索相同，则更新时间而不是添加重复行。历史仍最多保留 50 条。

Options 支持：

- 删除单条搜索历史。
- 清空全部搜索历史，并要求确认。
- 关闭历史记录只阻止新增记录，不自动删除已有数据。

备份继续包含搜索历史，隐私政策明确说明这一点。

## Popup 状态

Popup 的“当前网站状态”使用与 Content Script 相同的域名匹配逻辑：

- 精确域名规则命中时显示已标记。
- 开启子域名匹配时，子域名命中父域名规则也显示已标记。
- 不把 URL 规则或选择器规则描述为整个网站被标记。
- 非 `http`/`https` 页面显示中性不可用状态，而不是“当前网站正常”。

## 页面 Badge

保留工作区现有的页面 Badge 改动：工具栏 Badge 显示当前标签页的页面标记数量，而不是全局累计次数。

计数包含域名、URL、选择器和广告徽标。页面导航开始、扩展禁用或标记全部移除时将对应标签页 Badge 清零。消息必须校验发送方标签页和非负整数计数。

## Storage 写入一致性

所有对 `local:blocker` 的读改写操作进入同一串行队列，避免多标签页或搜索历史、统计、设置同时写入时相互覆盖。

只读 `get()` 不进入队列。写操作使用一个内部更新函数，在队列中读取最新状态、生成新状态并写回。现有公开方法签名保持不变。

备份恢复作为完整替换操作进入同一写队列。恢复数据继续进行版本与结构验证；数组和基础字段类型不正确时拒绝恢复，不允许通过字符串或任意对象生成畸形规则。

## 隐私与商店文案

隐私政策准确说明扩展在本地处理和存储：

- 屏蔽域名、URL、CSS 选择器。
- 搜索关键词、搜索引擎和时间戳。
- 屏蔽统计、设置、自定义语言和本地备份。
- 为识别结果而在白名单搜索引擎内读取 DOM 结构、文字标签和链接。

明确说明这些数据不上传、不出售、不与第三方共享。

商店描述使用“标记、遮盖搜索结果”而不是“完全隐藏”，删除“any search engine”，明确只支持四个列出的域名，并说明搜索历史可关闭和清空。

权限说明与最终 Manifest 保持一致，不再声称在所有网站运行。

## 依赖与页面元数据

- 移除未使用的 `@google/design.md` 生产依赖并更新 lockfile。
- Options 和 Popup 的 `<html lang>` 在运行时跟随当前语言设置。
- 版本号仍保持 `1.0.0`，本轮不自动提升版本。

## 测试策略

所有行为修复采用测试先行。

自动化测试覆盖：

- Manifest 和 Content Script 只包含八个精确白名单模式。
- 根域名与 `www` 规范化相同，其他子域名和地区域名不受支持。
- 禁用初始状态和运行时切换不会保留结果标记、扫描观察器、统计或 Badge，但保留浮动启用入口和独立的搜索历史能力。
- 规则搜索输入能更新父组件过滤结果。
- 域名和 URL 规范化边界。
- Popup 子域名状态与非网页状态。
- 搜索历史的四种导航、去重、单条删除和清空。
- 选择器规则显示 scope 并可撤销。
- 广告标记关闭再开启可以恢复扫描。
- Storage 多个并发写操作不丢失数据。
- Badge 当前标签页计数保留现有测试并补充禁用清零。
- 隐私和商店文案不包含过度承诺。

发布验证执行：

- `npm test`
- `npm run build`
- `npm run zip`
- `npm audit --omit=dev --json`
- 检查生产 Manifest、ZIP 文件列表和 Git diff。

真实 Chrome 手工验收需要加载 `.output/chrome-mv3`，逐个验证四个引擎的自然结果、广告、分页或动态加载、禁用切换、规则撤销和历史记录。该步骤不通过自动安装扩展完成，需要由用户在 Chrome 扩展管理页加载未打包扩展。

## 兼容与迁移

- 保留当前 `local:blocker` 存储键和备份版本 `1`。
- 保留旧规则数组和 `rules` 双写兼容模式。
- 保留已有 `customEngines` 数据但首发不使用。
- 已有 `<all_urls>` 权限在升级后缩减，不触发新增权限请求。
- 已有规则、统计和历史在升级后继续可读。
